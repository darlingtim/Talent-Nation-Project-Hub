# Project review workflow

Related issues: #6, #11, #8

1. A fellow submits a project -> status **Waiting for review**.
2. A mentor of that campus clicks **Approve** or **Reject** (optional reason).
3. The fellow gets a Discord DM and sees the status on their dashboard.
4. Editing a declined project sends it back for review.

Only mentors/Heads of the project's campus (or the site owner) can approve or decline; this is enforced by a database trigger.
